# Information Manager components
- Native icon selection is a shared AimEditor callback gated only by the verified icon-select marker, with one picker lock and category/image-specific paths outside configuration; V1/V2 use it instead of browser browse. Why: Python owns directory preferences and cancellation must not submit updates.
- Manager menu accepts both negotiated working profiles while retaining its independent integer marker and strict payloads; removal is list-only and favorites stay host-persisted. Why: WorkV2 must not hide an already advertised menu contract.
- Manager removal compares the editor snapshot path with managerPathKey in both controls and the shared dispatcher; selected preview never grants removal of the loaded project. Why: prevent active-entry removal without changing native commands.
- AimColorSwatches is shared by the actionbar and anchored AimGroupColorMenu; presentation swatches resolve to portable RGB and use existing confirmed configuration updates. Why: retain one palette, Python confirmation and Undo/Redo without a color properties dialog.
- Category/group creation uses the editor's selected real category and confirmed configuration update, then the tables' shared inline rename intent; aggregate views reject table drops, compact drag visibility is transient, and scoped form sizing keeps its footer outside the scroll body. Why: preserve destination identity, Python confirmation and expansion state.
- Presentation drag batches use one configuration update/history boundary; mixed V2 selections omit children only when their group transports them, and V1 incompatible mixed/direct-category row drops refuse explicitly. Why: visible selection and atomic Python confirmation must agree.
- PresentationAttributeForm reuses the original form interaction with supplied native attribute choices and group occurrence IDs, emitting configuration fields only; V1/V2 and creation share it without converting project values. Global disk save is unavailable outside the explicitly negotiated project-save profile; SuiteMenu consumes the editor's save availability and handler. JSON export independently requires the verified export marker and bounded update acknowledgement. Why: preserve Python authority and distinguish value saving from presentation export.
- Presentation contract 1 (lib/aim-presentation-contract.ts, components/presentation-import.tsx) is a separate strict consumer: Python prepares/converts/associates, the candidate is never mounted before confirmed apply, export is native JSON only, the organized model is held in memory and displayed by row id (never merged by number, never stored in the browser); messages with undeclared fields or a model tree not matching the configuration (ids, parent, position, number=String(num)) are rejected; after a project switch an unrecoverable presentation.get hides old values, keeps the configuration for export and offers retry, never a frontend-built model. Why: one-way migration owned by Python.
- Organized presentation: configuration-only moves use occurrence IDs in lib/organized-layout.ts; components/organized-presentation.tsx renders that layout using immutable Python rows by ID, never building a model or associating by number. Global/line/snapshot diagnostics remain internal, without a user-facing technical panel; menu/action-bar/save export the current canonical configuration only, never values; import replies after unmount are ignored, apply blocks closing, import and project selection never overlap. Why: presentation interactions must not change native facts or lose repeated occurrences.
- Organized category edits (name, embedded icon, confirmed removal of its own occurrences without transfer) mutate configuration only and use the existing update path; five visible columns share headers and cells with grips/actions inside them. Why: preserve independent occurrence identities and Python-owned values.
- Unset values render "Non renseigné"/"Indisponible" via ValueDisplay (checkbox keeps its box, mixed state); indicator text is never a value. Import opens Python's picker directly and only asks overwrite confirmation; group drag uses CATEGORY_HOVER_DELAY_MS and a dotted placeholder; recent-project history is host-owned and enabled only by Copilot's project_history_contract=1 (no local history). Why: recette 30/10.
- V2 column visibility consumes the editor's existing columns setting; one ordered visible definition drives tracks, headers, cells and spans, with Value always present and hidden-Data actions moved to Value. Why: keep table alignment without mutating Python state.
- Drag-and-drop shows a native drag image from lib/drag-ghost.ts (icon + title, aria-hidden, removed after snapshot/dragend) in addition to the dashed placeholder; manager section counters equal their rendered children. Why: the moved item and the destination are distinct cues, and counts must never describe invisible entries.
- Outside-row menu/grip use onAddOccurrence for configuration insertion, never move helpers with an invented occurrence ID; V2 shares the ordinary destination menu and can pass created configuration for a single confirmed update. Disabled Edit/Delete reuse UnavailableRowActions with focusable shared-help supports. Why: reuse row geometry while preserving native values and occurrence identity.
- Data-type help belongs to the icon support, not the cell containing row actions, in V1 and V2. Why: ancestor help must not mask the more specific hover or keyboard help of adjacent actions.
- AppTooltips keeps independent hover/focus triggers, prioritizes focus, preserves internal transitions, and suppresses stale reopening after explicit dismissal until a relevant entry/focus event; it restores stripped titles on target change/cleanup. Why: retain keyboard help without stale timers or native-title loss.
- NativeAttributesTable uses received native rows and existing column preferences without a presentation; destinationless actions stay disabled, while inline values and Reset retain their work-state guards. Why: complete visual structure must not invent occurrences or native permissions.
- Inline Reset reads the corresponding Python work.source attribute, with explicit source presence, and compares exact confirmed values; its fixed empty slot remains mounted and its click suppresses draft blur commits. Why: source restoration must preserve null/empty/zero and table geometry, independently of ∅.
- AIM mounts exactly one existing AimMessageDialog consumer of the shared app-dialog queue; askAimDiscard rejects concurrent creation and unmount cancels pending promises, without changing peer queue semantics. Why: confirmation must resolve once without loading SmartCatalog business state.
- Manager-only preview geometry stays scoped to aim-manager-preview; version sections are siblings of the leading user-added section, and footer Quitter invokes the existing cancel path without forced close. Preview group colors are parsed only under project_manager_preview_color_contract=1 (strict five-field groups, exact #RRGGBB kept) and rendered through --aim-group-accent; without the marker the four-field validator and neutral style stay. Why: visual changes cannot invent native facts or bypass exit protections.
