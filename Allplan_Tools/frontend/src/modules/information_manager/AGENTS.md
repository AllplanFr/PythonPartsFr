# Information Manager
Applies to every file here that loads or displays project attributes (AimEditor.tsx, lib/aim-project.ts, lib/aim-project-contract.ts, lib/aim-legacy.ts, components/). Presentation-component rules are in components/AGENTS.md.
- Python is the authority for Allplan data (reading, source resolution, number matching, validation, history, writing, prjtool). The frontend displays Python's complete display model, handles in-progress input and sends user intents; it never parses project.cfg/XML/prjatt.dat, never merges catalog and values, and keeps no independent business copy. Why: one owner for native data.
- Frontend validation is input assistance only and never replaces Python validation. Why: Python validates.
- Absent attribute stays unset (never injected as "0"); a received literal "0" is kept. Why: unset and zero are distinct project facts.
- A read error clears previous project data and shows a visible diagnostic, never presented as an empty project; nothing is inherited between projects. Why: an error must not look like an empty project.
- Contract 2 is connected (AIM_CONNECTED_CONTRACT=2): exact get_app_info identity, strict structural check, data.attributes displayed as received (value/valueState never recomputed); contract 1 is rejected, never adapted. project.select sends exactly {}; any reply with data replaces the whole display state (even ok:false), a refusal without data changes nothing. Why: Python resolves installations, sources and associations.
- Restore original presentation controls independently of native wiring; memory-value mutations require confirmed Copilot commands and envelopes, with no business file save/export, Allplan notification or prjtools. Keep current validators unchanged until then. Why: presentation reuse is allowed without inventing Python-owned draft semantics.
- The exact November 2 Copilot package is retained under contracts/; aim-working-contract consumes its WorkingState/WorkingRequests/WorkingResponses and independently gates work.* by working_state_contract=1. Adopt complete Python work states, synchronize work.get after mutations/presentation/import, and protect transitions/close with revision and explicit discard, never save/export/prjtools. Historical wire validators remain strict. Why: Python owns revisions, effective values and atomic transitions.
- AIM toolbar/menu icons are bundled copies of existing project artwork, not asset-proxy URLs or Allplan paths; the AIM brand icon is an embedded currentColor SVG redrawn from the user-supplied reference. Why: offline native windows must not depend on a workspace asset service or display an empty icon.
- Every contract-2 snapshot ends the host loading phase; selection remains busy through presentation.get, masks previous organized values while pending, and separates readable results from technical codes. General/menu/secondary imports share one guarded native opener in native or organized mode; browser legacy mode stays separate. Why: terminal snapshots must never look pending or bypass the native import lifecycle.
- Selection refusal text prioritizes a specific command message, excluding only the known generic notice "Projet AIM non charge ; consulter les diagnostics.", then diagnostics linked by its error code or established installation-selection causes; unrelated inventory diagnostics remain in technical details and an unknown cause stays neutral with manual retry. Why: a generic notice and diagnostic order are not evidence of causality.
- Presentation capability profiles: exactly five capabilities = existing import/get/export only; exactly six (presentation.update appended) = configuration edits submitted as {configuration} and Python's returned {configuration, report:null, model} adopted together; any other list is unrecognised. Unconfirmed drafts are never displayed as confirmed; failure keeps the confirmed presentation with retry/abandon; transport errors refetch presentation.get. Outside presentation is a display filter of Python-resolved attributes by String(num). Why: Python recomputes the model; the frontend never builds one.
- Images used at runtime are local files (imports, or public/ absolute paths for CSS custom properties, which lightningcss refuses as relative URLs), never /__l5e/ asset URLs. Why: native windows run offline.

- Project history: enabled only when get_app_info().project_history_contract === 1 (capability lists unchanged, presentation capabilities still decide update); project.recent {} lists host MRU entries, project.select {path} opens one; ok:true+status "cancelled" or a refusal without data leaves project and presentation untouched. No browser history. Why: Python owns the MRU.
- aim.css keeps only AIM-specific token overrides; shared tokens come from src/styles.css. Why: one common style base.
- Mixed presentation V2 is enabled only by presentation_tree_contract=1 and validated against the supplied mixed children tree; V1 remains separate, edits use presentation-tree configuration helpers and Python confirms the model. Why: preserve interleaving and prevent frontend association.
- Project manager is enabled only by project_manager_contract=1; aim-manager-contract validates project.source and manager envelopes, project-manager isolates cancellable preview requests, and AimEditor serializes protected opening with presentation/import. No browser project persistence. Why: Python owns the explicit list, loaded definitions and MRU independently.
- Virtual-view counters derive from the displayed model/configuration and Python attribute snapshot; manager rows expose unsupported native intents as disabled until their host contract exists. Why: never show browser-derived project facts or simulate durable project actions.
- Manager menu uses a separate strict consumer gated by project_manager_menu_contract=1 plus manager availability; host list/favorites refresh atomically after success, errors preserve confirmed state, removal invalidates only its preview. Capability lists and existing envelopes stay unchanged. Why: Python owns favorites, disk operations and MRU independently of the editor.
- Manager assignment is opt-in via project_manager_assignment_contract=1: strict projectInstallation fields are validated only for list/add/preview; exclusive sections use associated version/verificationVersion/prjPath, and unassociated/unknown/no-marker entries stay in the user section with uncertainty visible. Initial active selection never triggers preview, list is last_read only. Why: definition version is not membership and list must never scan or automatically reread projects.
- Value cells edit in place through InlineWorkingValue/ValueEditor (configured control in presentation, plain STR text outside presentation, per user product decision); Enter/blur sends one work.value.set for a changed value, Escape sends nothing, read_only/working capability lock every cell, and value edits never touch configuration. Why: value editing stays separate from definition editing and Python adopts the result.
- First selection uses the existing protected selectProject/work.transition only after the required initial snapshot and successful work.get adoption; initialization generations guard work responses and serialize manual/automatic opening. AIM's direct pywebview calls have no frontend dialog timer, while get_initial_data keeps its technical bound. Why: user dialog latency must not trigger retries or adopt obsolete state; frontend invalidation does not cancel Python.
- Project value save is a distinct negotiated WorkV2 consumer; preserve WorkV1 types/parser, use only confirmed session/revisions, direct save/status and status-only recovery, freeze protected mutations/transitions while unresolved, and adopt monotone session-compatible Python states without optimistic dirty changes. Why: acceptance and communication loss are not evidence of persistence.
